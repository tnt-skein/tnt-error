# Отказы и то, что видит человек

```lua
errors.define('customer.not_found', { status = 404, message = 'Клиента №{id} нет' })
local shown, err = errors.guard(handle, request)        -- паника — поломка с номером 4KJ7-QW9M
return err and errors.response(err, request) or shown   -- 404 со словом либо 500 с одним номером
```

## Зачем пакет

Отказ бывает двух видов, и путать их дорого.

**Ожидаемый** — тот, про который мы знали заранее: нет такого клиента,
пароль не подходит, поле не заполнено, сервер занят. У него есть понятная
человеку строка, и она идёт наружу целиком.

**Внутренняя поломка** — обращение к пустоте, отказ чужой библиотеки,
порванное соединение с базой. Наружу от неё уходит ровно две вещи: общая
фраза и опознаватель происшествия. Всё остальное — в журнал.

Пакет `tnt-error` держит это различие в одном месте. Без него каждый
пакет возвращает свою пару `nil, err`, а во что она превратится на экране,
решает тот, кто ближе к HTTP, — и решает каждый раз по-своему. Отсюда два
одинаково плохих исхода: либо наружу уезжает текст внутреннего отказа
со стеком и путями, либо человек видит «внутренняя ошибка» там, где ему
хватило бы одной внятной строки.

Поверх этого различия пакет даёт:

- **каталог отказов** — код, статус ответа и строка для человека
  объявляются один раз, а не сочиняются там, где отказ случился;
- **перехват паники** — `guard` превращает бросок во внутреннюю поломку
  с опознавателем, который читается вслух, и записью в журнале со стеком;
- **ответ наружу** — RFC 9457 по умолчанию, страница браузеру, слово
  на языке запроса; тайны вырезаны и из ответа, и из записи;
- **стык с границей HTTP** — слой для конвейера слоёв и обработчик
  отказов для роутера, при которых 404 роутера остаётся 404.

Зависит от [tnt-log](https://github.com/tnt-skein/tnt-log) (журнал
и правило тайн), [tnt-context](https://github.com/tnt-skein/tnt-context)
(опознаватель запроса), [tnt-id](https://github.com/tnt-skein/tnt-id)
(азбука Крокфорда), [tnt-template](https://github.com/tnt-skein/tnt-template)
(разметка страницы отказа), [tnt-validate](https://github.com/tnt-skein/tnt-validate)
(проверка объявлений и настроек) и
[tnt-external](https://github.com/tnt-skein/tnt-external) (внешние
зависимости и их подмена в проверках). Слой ставится в конвейер
[tnt-middleware](https://github.com/tnt-skein/tnt-middleware), обработчик
отказов — в роутер [tnt-router](https://github.com/tnt-skein/tnt-router),
но ни тот, ни другой пакету не нужен: запрос и ответ он берёт таблицами
по договору границы HTTP.

## Как пользоваться

```lua
local errors = require('tnt.error')

errors.define('customer.not_found', {
    status = 404,
    message = 'Клиента №{id} нет',
})

local function handle(request)
    local customer = storage.get(request.params.id)

    if customer == nil then
        return nil, errors.new('customer.not_found', { id = request.params.id })
    end

    return { status = 200, body = customer }
end
```

Обработчик оборачивается один раз, обычно слоем:

```lua
local shown, err = errors.guard(handle, request)

if err ~= nil then
    return errors.response(err, request)   -- статус, заголовки, тело строкой
end
```

Запрос вторым аргументом нужен двум: выбору вида ответа — браузеру
уходит страница, сценарию прежнее тело («Страница браузеру» ниже), —
и переводу, который находит по нему язык слова («Слово на языке
запроса»). Без него ответ прежний.

`guard` ловит панику (обращение к пустоте, `error()` в чужой библиотеке),
превращает её во внутреннюю поломку с опознавателем и пишет в журнал.
Ожидаемый отказ он пропускает как есть — и возвращённый парой,
и брошенный, в том числе брошенный под чужим перехватом («Отказ,
брошенный под чужим перехватом» ниже).

`response` собирает ответ целиком, и **тело в нём строка**: ответ уходит
в `http.server` как есть, а таблицу тот печатает клиенту как
`table: 0x...`. Кому нужна таблица — например чтобы дописать в неё своё
поле — берёт `render`: он отдаёт пару «тело таблицей, статус».

Готовое для HTTP берётся у самого пакета: `errors.middleware()` — слой
для `tnt.middleware`, `errors.handler()` — обработчик для
`router.on_error`. Отказ приходит обработчику **первым аргументом**;
что идёт за ним, ему безразлично.

## Чужой отказ на границе HTTP

Соседние пакеты отказывают раньше, чем дело доходит до каталога: роутер
отвечает 404 и 405 сам, до всякого обработчика. Такой отказ — не наш, но
и не внутренняя поломка, и пакет узнаёт его по договору:

```lua
{
    status = 405,                              -- обязательно: число, 4xx или 5xx
    message = 'этот способ здесь не поддерживается',  -- слово для человека
    code = 'customer.gone',                    -- код из каталога, если он есть
    incident = '4KJ7-QW9M',                    -- номер уже сделанной записи журнала
    headers = { allow = 'GET, HEAD, OPTIONS' },-- заголовки, которых требует статус
}
```

Обязательное здесь одно — **числовой `status`**, и признак это явный:
пакет не гадает по виду строки и по набору полей. `{ status = 'ok' }`
и запись работы `{ status = 1 }` отказом не считаются, успешный статус —
тоже: принять ответ за отказ значило бы молча превратить промах
вызывающего в готовый ответ клиенту.

Что делает пакет с таким отказом:

- **сохраняет статус** — 404 остаётся 404, а не становится 500;
- **сохраняет заголовки** — `Allow` при 405 требует RFC 9110 от ответа,
  а собирает ответ здесь каталог;
- **не выдаёт второго опознавателя** — пришедший с отказом номер ведёт
  к записи, которую уже сделал отказавший, а новый вёл бы в никуда;
- **не пишет «внутреннюю поломку»** — писать о ней второй раз значит
  положить в журнал две записи об одном запросе;
- **берёт своё слово, если чужого нет** — `Запрос отклонён` и код
  `refused`, когда отказавший не сказал ни слова, ни кода.

Отсюда и `errors.handler()` для `router.on_error`: он ставится одной
строкой и отвечает за всё сразу — и за 404 роутера, и за отказ, который
вернул обработчик маршрута.

Разница с ожидаемым отказом из каталога одна, и её стоит знать: договор
границы несёт **готовое слово**, а не шаблон с подстановками. Значит
`title` в ответе собирается из того же слова, что и `detail`, — имя рода
отказа, которое RFC просит не менять от случая к случаю, через границу
не проходит. Кому нужно и то и другое — ловит отказ раньше, слоем
`errors.middleware()`, где он ещё наш и целый.

## Цепочка причин

Накрыть причину можно двумя вызовами, и какой из них нужен, говорит
вызывающий, а не вид строки.

```lua
errors.define('mail.not_sent', { status = 502, message = 'Письмо не отправлено' })

local sent, err = mail.send(letter)

if not sent then
    -- объявленным отказом: свой код, свой статус, своя строка
    return nil, errors.wrap(err, 'mail.not_sent')
end
```

```lua
local ok, err = pcall(box.space.customers.insert, box.space.customers, tuple)

if not ok then
    -- готовым словом: род отказа и статус остаются от причины
    return nil, errors.explain(err, 'клиента не удалось сохранить')
end
```

`wrap` берёт **только объявленный код**. Незнакомый код — исключение:
это опечатка в коде, а не отказ клиенту.

`explain` берёт **только готовое слово** и показывает его целиком. Это
законно ровно потому, что слово написал разработчик прямо здесь; чужой
текст кладётся первым аргументом, а не вторым. Слово не строкой — тоже
исключение, как и незнакомый код: `explain(err, nil)` показал бы человеку
строку «nil», а таблица доехала бы до клиента целиком.

Наружу уходит верхний слой: «Письмо не отправлено». В журнале остаётся
вся цепочка — `tostring(err)` склеивает слои сверху вниз через двоеточие,
до чужого текста в самом низу:

```lua
local err = errors.wrap(errors.explain('сервер молчит', 'соединение не открылось'), 'mail.not_sent')

tostring(err)
--> Письмо не отправлено: соединение не открылось: Внутренняя ошибка.
-->   Назовите происшествие 4KJ7-QW9M тому, кто будет разбираться.: сервер молчит
```

Чужая строка внизу стала внутренней поломкой: отсюда в цепочке её общая
фраза и номер, который унаследовали верхние слои. Нижние слои человеку
не показываются никогда — в них лежит чужой текст, который ему ничего
не объясняет, зато рассказывает устройство узла тому, кто читает ответы.

## Вид ответа

По умолчанию — `problem+json` по RFC 9457:

```json
{
  "type": "urn:tnt-error:customer.not_found",
  "title": "Клиента №{id} нет",
  "status": 404,
  "detail": "Клиента №7 нет",
  "code": "customer.not_found"
}
```

`title` — имя рода отказа, одно и то же от случая к случаю (по умолчанию
это шаблон, как он написан); `detail` — что случилось именно в этот раз.
Начало `type` задаётся настройкой `type_base`: URN заменяется адресом
страницы с объяснением там, где такая страница есть.

`incident` и собранный из него `instance` появляются там, где о случившемся
написано в журнал: у внутренней поломки и у чужого отказа, пришедшего
со своим номером. У ожидаемого отказа из каталога происшествия нет, и
искать в журнале нечего.

Видов два готовых и сколько угодно своих:

```lua
errors.configure({ view = 'simple' })
--> { error = 'customer.not_found', message = 'Клиента №7 нет' }
```

```lua
-- Панель собрана как готовый JS и ждёт ровно такое тело
errors.configure({
    view = function(err, settings)
        return { error = { status = err.status, message = err.message } }
    end,
    content_type = 'application/json',   -- необязательно: это и есть умолчание
})
```

Своя функция получает отказ целиком — статус, код, опознаватель,
подстановки — и решает сама, что из этого попадёт в тело. Подпись ответа
следует за видом (`application/problem+json` у `problem`,
`application/json` у `simple` и у своей функции) и перебивается
настройкой `content_type`.

Настройки задаются по одной: необязательно всё, что пакет умеет
проставить сам.

```lua
local catalog = errors.registry({ view = 'simple' })   -- остальное по умолчанию

catalog:status()
--> { view = 'simple', content_type = 'application/json',
-->   type_base = 'urn:tnt-error:', instance_base = 'urn:tnt-incident:',
-->   page = 'builtin', debug = false, translate = false, codes = 1 }
```

`registry` заводит отдельный каталог со своими настройками; `configure`
настраивает общий на процесс, а `define` и прочее без `registry` идут
в него же.

Своя функция в `status()` показывается словом `custom`: прочитать её
глазами нечем, а место вида занять надо.

## Страница браузеру

Тело отказа написано для машины. Человеку, открывшему адрес браузером,
оно показывается строкой с фигурными скобками, и по ней не понять
ни что случилось, ни что делать дальше. Поэтому у отказа два вида,
и выбирает между ними сам запрос — заголовком `Accept` (RFC 9110,
§12.5.1):

| Что прислал клиент | Чем ответит каталог |
|---|---|
| `text/html,application/xhtml+xml,…` (браузер) | страница |
| `application/json`, `application/problem+json` | тело по договору |
| `*/*` (`curl`, `fetch` без заголовка) | тело по договору |
| `application/json, text/html;q=0.1` | тело: вес страницы меньше |
| заголовка нет вовсе | тело по договору |

Правило строгое нарочно: страница уходит тому, кто попросил её прямо —
назвал `text/html` (или `application/xhtml+xml`) **и назвал его весомее**,
чем тело данных. Равный вес отдаётся телу: клиент, назвавший оба вида
одинаково, ничего о себе не сказал, а тело отказа — договор, и менять
его молча нельзя.

Страница приходит с кодом отказа и подписью `text/html; charset=utf-8`;
заголовки отказа (`Allow` при 405) в ней те же, что и в теле.

### Что на странице

Заголовок по коду ответа («Страницы нет», «Что-то сломалось»), слово
из каталога — то же, что в теле, — и номера, по которым происшествие
находят в журнале: опознаватель происшествия и опознаватель запроса.
Второй берётся из контекста файбера — оттуда же, откуда его берёт
журнал, — так что номер на странице заведомо тот, по которому запись
найдут.

Ни стека, ни путей, ни заголовков запроса на ней нет: страницу читает
кто угодно. Всё подставленное экранируется — слово отказа несёт
подстановки из адреса запроса.

### Своя страница приложения

Настройка `page` — функция от данных страницы; что она вернула, то
и уедет клиенту:

```lua
errors.configure({
    page = function(shown)
        return views:render('errors.' .. shown.status, shown)
    end,
})
```

Данные (`TntErrorPageView`): `status`, `title`, `message`, `incident`,
`request_id`. Подробностей поломки среди них не бывает — страницу
разбора пакет рисует сам, и шаблон приложения её не покажет.

Пустота от своей страницы — «у приложения нет страницы на этот код»,
и рисует встроенная, молча. Сорвавшаяся страница и страница, отдавшая
не разметку, — тоже встроенная, но с записью в журнал: отказ, оставшийся
без ответа из-за опечатки в шаблоне, хуже некрасивой страницы.

`page = false` выключает страницы вовсе: браузер получит то же тело,
что и сценарий.

### Страница разбора поломки

Настройка `debug` (по умолчанию выключена) меняет страницу внутренней
поломки на страницу разбора. На ней:

- **место в коде** — первый кадр стека на Lua, а когда стека нет —
  `файл:строка` из слова поломки: так бывает у броска, который поймал
  чужой `pcall` и отдал парой `nil, err` строкой;
- **цепочка отказа** целиком, со всеми нижними слоями — теми, что
  наружу не идут никогда;
- **запрос**: способ, путь, поля строки запроса и заголовки;
- **стек**, если он у поломки есть: снятый `guard` на месте броска либо
  принесённый самой причиной («Стек, пришедший с причиной» ниже).

Только внутренней поломке и только по настройке: у ожидаемого отказа
разбирать нечего — он весь сказан словом, — и в разработке человеку
полезнее та же страница, что и в бою. Своя страница приложения при
разборе не зовётся: стек нужнее рамки сайта, а показать его шаблону
приложения всё равно нечем.

Тайны вырезаются и отсюда, тем же правилом, каким они вырезаются
из записи журнала: список подсказок один на все пакеты и живёт
в `tnt-log` («Тайны не уезжают» ниже). Значение заголовка
`Authorization`, куки и поля `token` на странице разбора — `[скрыто]`.

В боевом режиме от поломки на странице остаются два номера, и этого
довольно: по ним дежурный находит в журнале запись со стеком, причиной
и всем остальным.

## Слово на языке запроса

Слово каталога пишется по-русски прямо в объявлении, но берётся по коду,
а не склеивается по месту, — и коду с подстановками хватает, чтобы
сказать то же самое на другом языке. Переводит слово функция `translate`
из настроек: она получает отказ целиком и запрос, из-за которого
отказали, а отдаёт слово на языке запроса и сам язык. Переводчика пакет
не знает и от пакета переводов не зависит — связывает их тот, кто
собирает приложение:

```lua
local i18n = require('tnt.i18n')

local lang = i18n.new({
    locale = 'ru',
    messages = {
        ru = { hello = 'Привет' },
        en = { errors = { customer = { not_found = 'Customer {id} not found' } } },
    },
})

local catalog = errors.registry({
    view = 'simple',
    translate = function(err, request)
        local key = 'errors.' .. err.code
        local tag = type(request) == 'table' and request.locale or nil

        if tag == nil or not lang:has(key, tag) then
            return nil                                  -- уйдёт слово каталога
        end

        return lang:get(key, err.params, tag), tag      -- слово и его язык
    end,
})

catalog:define('customer.not_found', { status = 404, message = 'Клиента №{id} нет' })

local err = catalog:new('customer.not_found', { id = 7 })

catalog:response(err, { headers = {}, locale = 'en' })
--> { status = 404, body = '{"error":"customer.not_found","message":"Customer 7 not found"}',
-->   headers = { ['content-type'] = 'application/json',
-->               ['content-language'] = 'en', vary = 'Accept-Language' } }
catalog:render(err, { headers = {}, locale = 'ru' })
--> { error = 'customer.not_found', message = 'Клиента №7 нет' }, 404
```

Язык запрос несёт полем `locale`: его кладёт слой языка
[tnt-i18n](https://github.com/tnt-skein/tnt-i18n). Спрашивается запрос,
а не контекст файбера, потому что отказ парой `nil, err` проходит слой
языка насквозь, и рисует его страж отказов уже снаружи — там, где
контекста с языком нет, а запрос есть.

Что делает пакет с тем, что отдал перевод:

- **строка — слово на языке запроса**: `message` простого вида,
  `detail` у RFC 9457 и слово на странице. Имя рода отказа (`title`)
  и заголовок страницы по коду ответа остаются, какими их написали;
- **пустота — перевода нет**: уходит слово каталога, молча — строки
  на этот код у приложения может и не быть;
- **бросок или не строка — тоже слово каталога**, но с записью
  в журнал «слово отказа не переведено» (код отказа и причина):
  опечатка в строках перевода иначе жила бы до первой жалобы;
- **слово внутренней поломки без её опознавателя не берётся** — с той же
  записью: номер и есть весь ответ при 500, и правило то же, что у
  `redefine`;
- **тайны из слова вырезаются** тем же `scrub`, что и из слова `explain`:
  слово сложила чужая функция, и что она подставила, отсюда не видно.

Слово, сказанное `explain`, не переводится вовсе, и функцию о нём
не спрашивают: его написал разработчик для этого случая, и строка
по коду сказала бы меньше — даже на языке по умолчанию. Объявленный
отказ поверх него (`wrap`) переводится по своему коду.

Ответ каталога с переводом получает `Vary: Accept-Language` — всякий,
а не только переведённый: слово выбирает язык запроса, и кэш обязан
хранить ответ по языку и тогда, когда на этом языке слова не нашлось.
`Content-Language` ставится только переведённому слову и только если
перевод назвал язык: слово каталога написано на своём языке, и чужой
язык у него был бы неправдой. Язык, названный самим отказом
в заголовках, остаётся.

## Своё слово вместо чужого

Объявить занятый код второй раз `define` не даёт — два объявления одного
кода расходятся молча, и клиент однажды получает на свой запрос чужой
текст. Но приложению случается не согласиться со словом пакета, и тогда
замена говорится вслух:

```lua
errors.redefine(errors.INTERNAL, {
    status = 503,
    title = 'Не сейчас',
    message = 'Панель прилегла. Назовите {incident} дежурному.',
})
```

Свободный код переопределять нечего: `redefine` на неизвестный код —
исключение, и так ловится опечатка, которая иначе завела бы рядом второй
отказ о том же самом.

Слово внутренней поломки обязано называть `{incident}`. Оно и есть весь
ответ при 500: всё прочее в нём — общая фраза, одинаковая для всех
поломок, а номер — единственное, что связывает ответ с записью журнала.
Проверка стоит у самого каталога, а не у фасада: каталог открыт полем
реестра (`registry.catalog`), и запертая одна дверь из двух не заперта
вовсе.

## Опознаватель происшествия

`4KJ7-QW9M` — восемь знаков двумя группами, азбука Крокфорда без похожих
букв (`I`, `L`, `O`, `U`). Такой читается вслух по телефону, а `uuid`
на тридцать шесть знаков — нет. Азбука берётся у `tnt-id` (`tnt.id.crockford`),
которым пишется и ULID, а знаки остаются случайными: время, как в ULID
и UUIDv7, выдало бы снаружи, когда узел сломался (см.
[tnt-id](https://github.com/tnt-skein/tnt-id)).

Выдаётся он **ровно тогда, когда о происшествии написано в журнал**.
Номер, который никуда не ведёт, хуже отсутствующего: человек называет
его, а найти по нему нечего.

Роутер [tnt-router](https://github.com/tnt-skein/tnt-router) пишет свой
опознаватель тем же видом: его 404 и 405 приходят в каталог с номером,
который выдал роутер, и номера в ответах приложения одного вида —
`4KJ7-QW9M`, а не то UUID, то код. Договор записан в двух пакетах,
и расхождение ловит проверка стыка `test/boundary_test.lua`.

## Тайны не уезжают

Пароли, токены, ключи и куки вырезаются и из ответа, и из записи журнала.
Список имён и само правило — `secret` (похоже ли имя на тайну) и `scrub`
(тайны внутри строки) — одни на все пакеты и живут в `tnt-log`;
пакет отказов берёт их ссылками. Копий раньше было две, и они разъехались:
журнал не приводил дефис к подчёркиванию, и `X-Api-Key` в записи был
виден, а в ответе спрятан.

В запись журнала отказ попадает полями, а не строкой цепочки: у него есть
`__serialize`, отдающий код, статус, слово, опознаватель и причину (наш
отказ в причине — тем же видом). Стек и подстановки в запись не идут:
стек пишется отдельным полем только в записи о самом происшествии.
Тайны в слове и в причине прячет журнал (см.
[tnt-log](https://github.com/tnt-skein/tnt-log)).

`__serialize` действует не только в журнале. Консоль, `net.box`, `json`
и `msgpack` видят у отказа те же пять полей — `code`, `status`, `message`,
`incident`, `cause`, — а не все поля таблицы, как прежде: заголовков,
подстановок, рода и стека там больше нет. И `cause` там есть: прикладной
код, который сам вернёт отказ по iproto или положит его в JSON-тело ответа,
отдаст наружу и причину — чужой текст, ради сокрытия которого отказ
устроен цепочкой. Наружу безопасно отдавать только то, что собирает
`render`: код, род, слово и опознаватель, без причины.

Адрес с учётными данными (`postgres://root:hunter2@db/main`) прячется
целиком в части пароля, остальное остаётся видимым: по нему разбираются,
куда именно не удалось подключиться.

## Стек, пришедший с причиной

Запись о внутренней поломке несёт стек отдельным полем `traceback`,
и снимает его `guard` — на месте броска, пока стек ещё есть. Но бросок
ловит и тот, кто стоит ниже каталога: конвейер слоёв зовёт обработчик
под своим перехватом, и к стражу поломка доходит уже отказом, со стеком,
размотанным чужим `xpcall`. Снять его здесь нечем, и без помощи запись
говорила бы, что сломалось, но не как туда пришли, — а при поломке
в общей функции, которую зовут из десяти мест, вызывающий и есть ответ.

Поэтому стек принимается и от самой причины — таблицы со строкой в поле
`traceback`. Так устроен отказ упавшего шага конвейера
[tnt-middleware](https://github.com/tnt-skein/tnt-middleware): слово в `message`, стек
в `traceback` — тот же вид, что у внутренней поломки этого пакета.
Признак один и явный — строка в `traceback`; ничего сверх неё
не угадывается:

```lua
local _, err = errors.guard(chain:wrap(handler), request)   -- обработчик бросил

err.traceback
--> "\nstack traceback:\n\t[C]: in function 'error'\n\tsrc/app/handlers.lua:12: in function <…>\n\t…"
```

Стек, снятый `guard`, важнее принесённого: снятый — стек заведомо,
а поле чужой таблицы — стек только по договору. Поле читается мимо
метатаблицы: о причине пишут там, где поломка уже случилась, и чужой
`__index`, бросив, унёс бы с собой запись о первой. Причина в записи
остаётся словом, без стека: отказ конвейера печатает себя своим словом,
а стек лежит рядом, своим полем.

С тем же стеком рисуется и страница разбора: место в коде — первый кадр
на Lua, то есть строка самого обработчика, и раздел «Стек» целиком.

## Отказ, брошенный под чужим перехватом

Обработчик вправе отказать и броском, а не парой: глубоко в разборе
запроса вернуть пару бывает не через что. `guard`, поймав такой бросок
сам, пропускает отказ как есть. Но бросок ловит и тот, кто стоит ниже
каталога: конвейер слоёв зовёт обработчик под своим перехватом и отдаёт
стражу отказ упавшего шага — слово «обработчик упал: …» и стек, — а по
слову статус и код уже не узнать. Без помощи тот же отказ отвечал бы
своим статусом, вернись он парой, и поломкой 500 с номером
происшествия, будь он брошен.

Поэтому каталог заглядывает в поле `raised` причины — туда отказ
упавшего шага конвейера
[tnt-middleware](https://github.com/tnt-skein/tnt-middleware) кладёт
брошенное как есть. Брошенное судится теми же двумя вопросами, что
и сама причина:

- **наш отказ** — узнаётся по метатаблице — возвращается как есть:
  без второго опознавателя и без записи о поломке;
- **чужой отказ границы HTTP** — узнаётся по числу в `status` —
  принимается со своим статусом, словом и заголовками.

```lua
local _, err = errors.guard(chain:wrap(function()
    error(errors.new('customer.not_found', { id = 7 }))
end), request)

errors.code_of(err)   --> 'customer.not_found'
err.status            --> 404
```

Всё прочее брошенное — строка, объект ошибки, таблица без статуса —
остаётся поломкой, и причиной в записи идёт отказ упавшего шага
целиком: его слово называет упавший шаг, а стек лежит рядом («Стек,
пришедший с причиной» выше). Поле читается мимо метатаблицы, по той же
причине, что и стек. `wrap` и `explain` приводят причину тем же `of`
и накрывают брошенный отказ так же, как возвращённый.

## Причина в записи о поломке

Запись о внутренней поломке несёт причину полем `reason`, и это всегда
строка — та же, что лежит в `cause` у отказа и печатается в цепочке.
Строка-причина пишется как есть, а всё, что печатает себя само, — своей
печатью: `box.error` — своим текстом, отказ соседа с `__tostring` — тем,
что он напечатал. Двоичная строка, откуда бы она ни пришла, становится
отметкой `[не UTF-8, N байт]` (почему — ниже).

Простая таблица напечатала бы только свой адрес, `table: 0x…`, и номер
происшествия вёл бы в запись, из которой не понять, что сломалось.
Поэтому такая таблица описывается JSON своей копии:

```lua
errors.of({ code = 'storage.down', password = 'hunter2', nodes = { 'a', 'b' } })
--> внутренняя поломка incident=NCK9-B243
-->   reason="{\"password\":\"[скрыто]\",\"nodes\":[\"a\",\"b\"],\"code\":\"storage.down\"}"
```

Как устроена копия:

- **тайны прячутся по именам ключей до кодирования**, тем же правилом,
  что и подстановки: значение под `password` заменяется целиком, со всем
  поддеревом. В тексте JSON имя и значение — уже просто соседние слова,
  и поддерево под тайным именем образцы строки не узнали бы. Готовый
  текст проходит ещё и `scrub`: пароль в адресе прячется и внутри поля;
- **не глубже восьми уровней** — глубже стоит `[глубже]`;
- **не больше 64 пар на всех уровнях вместе** — описание, в которое вошли
  не все пары, кончается знаком `…`;
- **кольцо** — отметкой `[кольцо]`; две ссылки на одну таблицу из соседних
  полей кольцом не считаются;
- **ключ, которого `json` не берёт** (boolean, дробь, бесконечность,
  таблица), — своей печатью. Целый ключ остаётся числом, пока double
  хранит его точно (до 2^53), и массив остаётся массивом;
- **значение, которого `json` не пишет** (функция, userdata, cdata, кроме
  64-битного целого и `box.NULL`), — своей печатью: uuid, decimal, дата
  и кортеж печатают себя сами. Не сумевшее напечататься — своим родом,
  `[userdata]`;
- **двоичная строка в поле или в ключе** — отметкой `[не UTF-8, N байт]`:
  журнал заменяет негодную строку поля целиком, и одно двоичное поле
  стёрло бы из записи всё описание;
- **таблица, чья печать бросила или дала не строку**, — своими полями:
  они скажут о ней больше, чем пустая отметка.

Описание собирает `require('tnt.error.secret').describe`, пределы лежат
там же: `DEPTH` (8) и `ENTRIES` (64).
Длина описания — не больше окна вырезания тайн, 8192 байта, дальше `…`;
в записи журнала поле режется ещё и по потолку строки, 4096 байт.

Описание не бросает ни на каком входе: его пишут там, где поломка уже
случилась, и второй бросок унёс бы с собой запись о первой. Тем же
описанием названа причина в исключении `wrap` с незнакомым кодом:

```lua
errors.wrap({ code = 'storage.down' }, 'timeout')
--> ошибка: отказ timeout не объявлен: объявите его define либо накройте
-->   причину словом через explain (причина: {"code":"storage.down"})
```

## Крюки внутренней поломки

О поломке каталог пишет в журнал сам, и запись эта одна. Но журнал —
не единственный, кому нужно знать о поломке: приёмнику происшествий,
который группирует одинаковые поломки и считает их повторы, нужно то же
событие с тем же опознавателем — по нему событие сходится с записью
журнала и с ответом клиенту. Поэтому о поломке сообщается там, где номер
выдан, а не выше по стеку, где его пришлось бы угадывать:

```lua
errors.hook('app.alert', function(failure, cause)
    -- failure — та же внутренняя поломка, что ушла вызывающему:
    --   failure.incident, failure.traceback, failure.cause (описание причины)
    -- cause — причина как есть: строка, box.error, таблица
    alerts.push(failure.incident, cause)
end)

errors.of('сервер молчит')
--> запись «внутренняя поломка» в журнале, затем крюк app.alert

errors.hooks()             --> { 'app.alert' }
errors.hook('app.alert', nil)
```

- **Кто слушает, пакет не знает.** Крюк приходит аргументом, и
  зависимости от слушателя у каталога нет.
- **Крюки общие на процесс, а не на каталог.** Каталоги заводятся и внутри
  пакетов — у ядра приложения свой, у панели свой, — и до них приложение
  не дотягивается: крюк одного каталога не услышал бы поломок остальных.
- **Крюк зовётся после записи**: номер к этому мигу уже ведёт в журнал.
  Отказы, которые поломкой не считаются, — объявленный, чужой отказ
  границы HTTP, — крюков не будят: о чужом с номером уже написал
  отказавший.
- **Причина — как есть.** В отказе она лежит описанием — строкой для
  журнала с вырезанными тайнами. Слушателю со своим разбором нужна она
  сама: цепочка ошибок box, отказ со стеком внутри. Тайны в ней
  не вырезаны, и прятать их — дело слушателя.
- **Порядок — порядок постановки**, замена оставляет крюк на месте,
  снятый и поставленный снова встаёт последним. Повторная постановка под
  тем же именем безвредна: слушателя ставят и при запуске, и при
  перечитывании настроек.
- **Крюк зовётся под `pcall`.** Бросок слушателя не уносит с собой отказ,
  который уже собран и записан: о сорвавшемся крюке пишется `warn`
  «крюк внутренней поломки «имя» не отработал» с номером происшествия,
  и остальные крюки зовутся дальше. Уступать и ждать крюку нельзя:
  поломку заводят и посреди транзакции.
- **Негодные аргументы — исключение на строке вызывающего**: «имя крюка —
  непустая строка, а не nil», «крюк — функция, а не string».

## Чем пришлось поступиться

- **Пакет не угадывает — значит, вызовов два.** `wrap` и `explain`
  делают почти одно и то же, и помнить разницу приходится вызывающему.
  Один вызов на оба случая был, и он решал по виду строки: латиница
  без пробелов считалась кодом. Чужое `timeout` уходило искать себя
  в каталоге, не находилось и роняло узел — 500 вместо внятного отказа.
  Два вызова дешевле такой догадки.
- **Незнакомый код — исключение, а не отказ.** Опечатка
  `customer.not_fond` внутри обработчика станет 500 с опознавателем,
  а не тихим показом чужого текста. Это осознанный выбор: молчаливый
  показ кода вместо сообщения хуже падения.
- **`get`-подобных умолчаний нет**: строка, переданная в `errors.of`,
  считается внутренней поломкой, а не сообщением человеку. Иначе любой
  текст из чужой библиотеки мог бы уехать на экран.
- **Своя функция вида — это договор без проверок.** Пакет отдаёт ей
  отказ и настройки и берёт что вернули: ни поля тела, ни подпись
  ответа он больше не сводит. Опознаватель в таком теле появляется,
  только если его туда положили, — и об этом легко забыть ровно
  в том ответе, где он нужнее всего.
- **`redefine` меняет объявление молча для тех, кто его уже прочитал.**
  Пакет, сохранивший `title` в переменную при загрузке, продолжит жить
  со старым словом. Объявления читаются по коду и в тот момент, когда
  отказ заводят, — так делает и сам пакет, — но чужой код к этому
  ничем не обязан.
- **`guard` возвращает пару**, а не все значения функции: третьему
  значению в договоре «значение, отказ» негде разместиться.
- **Причина-таблица в записи — строка JSON, а не объект.** По её полям
  сборщик журналов не ищет, зато `reason` у всех записей о поломке одного
  рода: поле, которое бывает то строкой, то объектом, сборщик не разложит
  по одной схеме. Пары в описании идут в порядке `pairs`, то есть в любом,
  и у таблицы шире 64 пар в описание попадают какие придётся.
- **`__serialize` при описании не спрашивается.** Таблица без `__tostring`
  описывается своими полями, даже если `__serialize` показал бы её иначе,
  а пометка `__serialize = 'map'` теряется: пустая таблица пишется `[]`.
  Закрытая метатаблица (`__metatable`) не показывает, есть ли печать,
  и такая таблица тоже описывается полями.
- **Слово чужого отказа идёт наружу на веру.** Договор границы называет
  `message` строкой для человека, то есть написанной разработчиком, —
  ровно как второй аргумент `explain`. Проверить это отсюда нечем: положи
  сосед в `message` ответ чужой библиотеки, и он уедет клиенту. Обратное —
  заменять чужое слово своим всегда — оставило бы 404 роутера без единственной
  внятной фразы, какая у него есть.
- **Через границу проходит готовое слово, а не шаблон.** Значит `title`
  собирается из него же, и `detail` у такого отказа не будет: RFC 9457
  просит, чтобы `title` не менялся от случая к случаю, а чужой отказ
  приносит уже подставленную строку. Кому нужны оба поля — ловит отказ
  слоем, пока он ещё свой.
- **`response` отдаёт тело строкой, а не таблицей.** Ответ уходит
  в `http.server` как есть, а таблицу тот печатает клиенту как
  `table: 0x...`. Кто разбирал `response(err).body` как таблицу —
  переходит на `render`, который её и отдаёт.
- **О клиенте судим по одному заголовку.** Браузер, у которого `Accept`
  срезал прокси, и клиент, приславший `*/*`, получают тело, а не
  страницу. Обратное правило — «показывать страницу всем, кто не просил
  JSON» — меняло бы договор отказа молча, и первым это заметил бы
  чужой сценарий, разбирающий наше тело.
- **Стек бывает не у всякой поломки.** Он есть у того, что каталог
  перехватил сам, — у `guard` в прикладном коде, в задаче планировщика,
  в функции iproto, — и у причины, принёсшей его полем `traceback`, как
  отказ упавшего шага конвейера слоёв. Бросок, пойманный чужим `pcall`
  и отданный парой `nil, err` строкой, стека не несёт: он размотан
  раньше, чем дошёл сюда, и страница разбора называет только место
  из слова поломки.
- **Принесённый стек — на веру.** Строка в `traceback` чужой таблицы
  берётся стеком без проверки вида: проверить её отсюда нечем, как
  и слово чужого отказа. Кто кладёт туда не стек, получит это
  в записи о поломке и на странице разбора.
- **Брошенное в `raised` — тоже на веру.** Таблица, положившая в поле
  `raised` наш отказ или отказ границы HTTP, отвечает им, чья бы она
  ни была: признак — само поле, а не тот, кто его заполнил. Лазейки
  в этом нет: кто может положить туда отказ, мог бы и вернуть его прямо.
- **`is`, `code_of`, `expected` и `incident_of` смотрят только на сам
  отказ.** Отказ упавшего шага, несущий брошенный отказ, для них чужой:
  `errors.code_of(fall)` — `nil`. Кому нужен код брошенного — приводит
  причину `of` и спрашивает у того, что вернулось.
- **Страница разбора перебивает страницу приложения.** В разработке
  стек нужнее рамки сайта, а показать его шаблону приложения всё равно
  нечем: подробностей поломки ему не дают.
- **Переводится слово, а не страница и не имя рода.** `title` у RFC 9457
  и заголовок встроенной страницы по коду ответа остаются, какими их
  написали, и встроенная страница по-английски говорит одним словом
  отказа, а подписи у неё прежние. Переводить их значило бы завести
  второй договор с переводом — на имя рода и на каждую подпись
  страницы. Приложению на нескольких языках — своя страница (`page`),
  где заголовок и подписи берутся из его строк.
- **Слово `explain` не переводится.** Посетитель на другом языке
  прочтёт его как написано. Кому нужно слово на всех языках — объявляет
  код и накрывает причину `wrap`.
- **`title` по умолчанию — шаблон как написан** (`Клиента №{id} нет`).
  RFC требует, чтобы `title` не менялся от случая к случаю; кому нужен
  опрятный вид — пишет `title` в объявлении отдельно.
- **Крюк видит тайны причины.** Причину он получает как есть, а не
  описанием: слушателю со своим разбором описания мало. Вырезать тайны —
  его забота, и крюк, отдающий причину наружу как есть, отдаст и их.
- **Настройка заменяет прежнюю целиком, а не по полю.** `configure`
  зовётся один раз при запуске, и «что-то осталось от прошлого раза»
  здесь только запутывало бы. Объявленные отказы при этом остаются:
  их заводят пакеты при загрузке, то есть до всякой настройки.

## Проверки

Каталог, перехват — и свой, и чужой, с брошенным в `raised`, — вид
ответа, страница, перевод и вырезание тайн проверяются против
исходников пакета, с настоящим журналом `tnt-log`:
запись о поломке ловится и сверяется полями — опознаватель, причина,
стек, — а не строкой. Случайность опознавателя подменяется
(`require('tnt.error.incident')._set_source({ random = … })`), чтобы номер
в ответе и в записи журнала сверялся точным значением. Описание причины
проверено на входах, на которых бросает `json` или сам `tostring`: кольцо,
глубина за пределом, ключи-дроби и ключи-таблицы, cdata, двоичные строки,
метатаблица, бросающая из `__index` и `__tostring`.

Крюки проверены на том, что они слышат: номер и стек поломки, причину
той же таблицей, поломку любого каталога процесса и тишину на отказах,
которые поломкой не считаются, — и на том, что сорвавшийся крюк
не стоит ни отказа, ни соседних крюков.

Стык с границей HTTP проверен в настоящем роутере `tnt-router`: 404 и 405
роутера проходят через `errors.handler()` со своим статусом, заголовком
`Allow` и опознавателем роутера, и опознаватели обоих пакетов пишутся
одним видом.

Проверки лежат в `test/` и идут на luatest. Покрытие строк — 100 %,
убитых мутантов — 100 %.
