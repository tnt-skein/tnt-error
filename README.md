# tnt-error

Отказы для Tarantool: каталог кодов, перехват паники и ответ наружу.
Ожидаемый отказ уходит человеку целиком — кодом, статусом и строкой
по-русски, — а от внутренней поломки наружу уходит только общая фраза
и опознаватель происшествия; подробности со стеком остаются в журнале.

```lua
local errors = require('tnt.error')

errors.define('customer.not_found', { status = 404, message = 'Клиента №{id} нет' })

local function handle(request)
    local customer = storage.get(request.params.id)

    if customer == nil then
        return nil, errors.new('customer.not_found', { id = request.params.id })
    end

    return { status = 200, body = customer }
end

local shown, err = errors.guard(handle, request)   -- паника — поломка с номером 4KJ7-QW9M

if err ~= nil then
    return errors.response(err, request)            -- статус, заголовки, тело строкой
end
```

Зависит от `tnt-log`, `tnt-context`, `tnt-id`, `tnt-template`,
`tnt-validate` и `tnt-external`.

## Зачем

- **Чужой текст наружу не выходит.** Строка, которую не писал
  разработчик, — отказ библиотеки, текст базы, стек — становится
  внутренней поломкой: человеку — «Внутренняя ошибка. Назовите
  происшествие 4KJ7-QW9M…», дежурному — запись журнала со стеком
  и причиной по тому же номеру.
- **Пакет не угадывает.** Причину накрывают объявленным кодом (`wrap`)
  или готовым словом разработчика (`explain`), и по виду строки пакет
  не решает ничего.
- **Номер читается вслух.** Восемь знаков азбуки Крокфорда без похожих
  букв, двумя группами, и выдаётся он только тогда, когда запись
  о происшествии уже сделана.
- **Ответ по стандарту.** RFC 9457 (`application/problem+json`)
  по умолчанию, простой вид и своя функция — настройкой; браузеру,
  попросившему `text/html`, — страница, в разработке — страница разбора
  со стеком и запросом.
- **Граница HTTP.** Чужой отказ — таблица с числовым `status` — сохраняет
  статус, заголовки и номер: 404 роутера остаётся 404, `Allow` при 405
  доходит до ответа.
- **Тайны не уезжают.** Пароли, токены, ключи и куки вырезаются из ответа,
  из страницы и из записи журнала одним правилом — правилом `tnt-log`.

## Установка

```sh
tt rocks install tnt-error --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-error.git
cd tnt-error && tt rocks make
```

## Как пользоваться

| Вызов | Что делает |
|---|---|
| `define(код, { status, message[, title, type] })` | объявляет отказ; занятый код — исключение |
| `redefine(код, объявление)` | меняет объявление вслух; слово поломки обязано назвать `{incident}` |
| `new(код[, подстановки])` | ожидаемый отказ по объявленному коду |
| `of(что угодно)` | приводит к отказу: наш, чужой отказ границы или поломка |
| `wrap(причина, код[, подстановки])` | накрывает причину объявленным отказом |
| `explain(причина, слово)` | накрывает причину готовым словом разработчика |
| `guard(fn, ...)` | зовёт функцию под перехватом; отдаёт пару «значение, отказ» |
| `response(err[, запрос])` | ответ целиком: статус, заголовки, тело строкой или страница |
| `render(err[, запрос])` | тело таблицей и статус |
| `middleware()`, `handler()` | слой конвейера и обработчик отказов роутера |
| `hook(имя, крюк)`, `hooks()` | крюки внутренней поломки: кому ещё сказать о ней с тем же номером |
| `configure(настройки)`, `registry(настройки)` | общий каталог и отдельный со своими настройками |
| `is`, `code_of`, `incident_of`, `expected` | вопросы к отказу |

Настройки: `view` (`problem`, `simple` или функция), `content_type`,
`type_base`, `instance_base`, `page` (`true`, `false` или функция),
`debug`, `translate` — функция перевода слова на язык запроса.

```lua
errors.define('mail.not_sent', { status = 502, message = 'Письмо не отправлено' })

local sent, err = mail.send(letter)

if not sent then
    return nil, errors.wrap(err, 'mail.not_sent')   -- наружу: 502, «Письмо не отправлено»
end

errors.render(errors.new('customer.not_found', { id = 7 }))
--> { type = 'urn:tnt-error:customer.not_found', title = 'Клиента №{id} нет',
-->   status = 404, detail = 'Клиента №7 нет', code = 'customer.not_found' }, 404

router.on_error(errors.handler())   -- 404 и 405 роутера — своим статусом, упавший обработчик — номером
```

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov, рок http и роутер для проверок стыка в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

214 проверок, покрытие строк — 100 %, убитых мутантов — 100 %
(533 мутанта в двенадцати модулях). Запись о поломке
сверяется полями настоящего журнала `tnt-log`, стык — в настоящем роутере
`tnt-router`: его 404 и 405 проходят через обработчик отказов со своим
статусом, заголовком и номером.
